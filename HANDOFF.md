## Что это

Два независимых раздела на одном сайте:
1. **Публичная визитка** (`index.html`) — портфолио для LinkedIn, без логина
2. **Личный дашборд** — трекер привычек/целей/навыков с баллами, за логином (email+пароль),
   многопользовательский (задумано так, что и другие люди могут зарегистрироваться и
   пользоваться отдельно от Владимира)

## Стек

- Фронтенд: чистый HTML/CSS/JS, без сборки, без фреймворков
- Бэкенд: Supabase (Postgres + Auth + Storage), бесплатный тариф
- Хостинг: Netlify (сейчас через Netlify Drop, есть план перейти на git-автодеплой — см. README)

## Известный паттерн багов в этом проекте (важно!)

**Самая частая причина "не работает"**: где-то в коде Supabase-запрос падает с ошибкой,
которая раньше тихо проглатывалась (`await sb.from(...).upsert(...)` без проверки `error`).
Почти всегда причина — не прогнана какая-то миграция, из-за чего колонки/функции не существуют.

Сейчас в большинстве мест (дашборд, онбординг) ошибки уже показываются алертом/тостом с
конкретным текстом и подсказкой, какую миграцию прогнать. Но если добавляешь НОВЫЙ код —
**всегда проверяй `error` из ответа Supabase и показывай его пользователю**, не глотай молча.

## Архитектурные решения, которые стоит знать

- **RLS (Row Level Security)** включён на все таблицы, доступ у каждого только к своим
  строкам (`auth.uid() = user_id`), кроме публичных функций для лидерборда/сообщества —
  они `security definer` и намеренно агрегируют данные всех пользователей, но отдают
  только имя/баллы/аватар/добровольную заметку, не сырые персональные метрики
- **Приватность лидерборда**: `profiles.leaderboard_visible` — можно скрыть себя,
  фильтрация на клиенте (в community.js), не на уровне RLS
- **Метрики полностью кастомные** — не захардкожены, каждый пользователь настраивает свои
  через `metrics` (тип number/boolean/multiselect + цель + категория)
- **Категории метрик** (`metric_categories`) — общий справочник для сравнения между
  пользователями (чтобы "Отжимания" у одного и "Push-ups" у другого сравнивались, если
  оба привязаны к одной категории). Можно создавать свои категории прямо из формы метрики
- **Баллы** считаются в двух местах параллельно: клиентский JS (`config.js: calcTotalPoints`)
  для собственных нужд пользователя, и серверная SQL-функция `calc_user_points()` для
  сообщества — если меняешь логику баллов, поменяй ОБА места
- **Streak** считается SQL-функциями `calc_perfect_streak` / `calc_category_streak`
  (в migrations/005), а также client-side по каждой метрике отдельно в `dashboard.js`
  (`loadStreaks()`) — два разных механизма для разных нужд (лидерборд vs личный дашборд)

## Что сделано (полный список фич)

- Регистрация/вход, анкета при первой регистрации с выбором целей и метрик (можно
  раскрыть список и вручную отметить, какие метрики нужны)
- Настраиваемые ежедневные метрики (число/да-нет/выбор), редактирование прямо в
  форме с блокировкой нерелевантных полей по типу
- Долгосрочные цели: категории, многоэтапные цели, редактирование/удаление
- Навыки: настраиваемый шаг прогресса и баллы за освоение, подсказки-идеи, раздел книг
- Словарь английского языка
- Магазин за баллы с картинками (по ссылке или загрузкой)
- Профиль: аватарка, возраст (редактируемый), вес/жир/мышцы с прогрессом от первой записи
  (не просто дельта от предыдущей, а с учётом цели — зелёным/красным)
- Настраиваемые графики на дашборде — выбор каких показывать и в каком порядке
- 🔥 Streak-серии — общие и по каждой метрике
- Сообщество: лидерборд (общий + по друзьям), лента "что сделали сегодня" (списком пунктов,
  не текстом), сравнение по категориям с реальными цифрами (не только баллами) + личный
  график, приватность (можно скрыться), подписка на друзей по email
- Темы оформления дашборда (Тёмная/Светлая/Розовая)
- EN/RU — полностью только на визитке/входе/шапке навигации, остальное на русском
- Тосты вместо alert() при сохранении дня
