# 74.3 — аудит состояний ошибок и восстановления (агент 7, 2026-10-29)

Метод: статический разбор исходников всех `web-*/src` (без запуска), затем проверка найденных мест в тестах.

## Что уже хорошо
- `friendlyError.ts` (понятный текст вместо сырого сообщения базы/сети) есть в каждом пилоте; адрес Supabase и «TypeError» пользователю не показываются.
- Пустых `catch {}` в рабочем коде нет, кроме осознанных «лучшее из возможного» (регистрация сервис-воркера, подсказка установки): они ничего не скрывают от пользователя.
- Ошибки действий (сохранить, купить, получить награду) показываются через `actionError` понятным текстом.

## Что было плохо (найдено)
- **12 мест, где ошибка ЗАГРУЗКИ — серый `<p>` без «Повторить» и без `role="alert"`**: achievements, challenges, community×3 (`App.vue`, `CategorySection.vue`), dashboard×2 (`App.vue`, `ChartsSection.vue`), goals, milestones, shop, skills×2 (навыки и книги). Чтобы повторить, нужно было перезагружать страницу целиком.
- В магазине сообщение об ошибке не сбрасывалось при повторной загрузке.
- Подсказки «нет сети» нигде не было: человек видел общий «не удалось загрузить» и не понимал, что дело в связи.

## Срез 1 (v6.63, сделано)
`LoadError.vue` (сообщение + слот-подсказка + «Повторить» с занятой кнопкой на время запроса + отдельная строка «Нет сети…», `role="alert"`, кнопка не ниже 44 px) подключён в **6 пилотах**: shop, goals, skills (2 места), achievements, milestones, challenges. Копия компонента одинакова во всех пилотах и правится только через `scripts/apply_load_error.py`. Страж `web-dashboard/src/loadErrorSites.test.ts`: голый серый «не удалось загрузить» в новых местах не пройдёт; копии не разойдутся; ключи есть на двух языках; остаток явно перечислен в `ALLOW`.

## Осталось
1. **Срез 2:** dashboard (`App.vue`, `ChartsSection.vue`) и community (3 места) — у них несколько независимых загрузчиков, нужно решить, что именно «повторяет» кнопка. После перевода убрать места из `ALLOW` стража.
2. Состояние «загрузка»: у большинства пилотов только мигающий текст/ничего — скелетоны для списков (shop, goals, challenges) отдельным срезом.
3. Пустые состояния («ничего нет — вот что сделать») — отдельный аудит по пилотам.
4. Вход офлайн: сервис-воркер отдаёт оболочку, но данные не кэшируются; показывать «последние данные на …» можно только после решения владельца (хранение данных на устройстве).
