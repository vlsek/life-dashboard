## 1. Languages — схема адресов

**Предложение (вариант A):**
- Пилот: `/languages/` (`web-languages/` → сборка в `../languages`, `-vue` убираем).
- Классика: `/legacy/english.html` + `/legacy/english.js` (старое имя файла + префикс `/legacy/` —
  ровно схема, которую владелец задал 2026-09-28).
- Ключ страницы в `pages[]` остаётся `english` (`nav_english`); поле `vue` → `languages/`.
  Переименование подписи в «Изучение языков» — отдельный пункт `docs/BACKLOG.md` (строка про
  «Изучение языков»), в этот переезд не смешиваем.

**Почему так:** в `web-languages/vite.config.ts` уже записано пожелание владельца «в итоге переименовать
в Languages» — у пилота имя `languages` есть с самого начала. А правило фазы 2 «legacy = текущее имя
ванильного файла». Оба условия выполняются без исключений.

**Отклонённая альтернатива (B):** `/legacy/languages.html` — переименовать классику при переезде.
Смешивает два риска (переименование и перенос) и ломает правило «legacy = старое имя».

**Что нужно править (по рецепту, без сюрпризов):** `web-languages/vite.config.ts`; `english.html/js` →
`legacy/` (+ `../` в путях); `sw.js` (ASSETS + CACHE_NAME); строка `english` в `pages[]` (`config.js`);
`'/languages-vue/'` → `'/languages/'` в 12 `AppShell.vue`; `web-languages/src/smoke.test.ts`
(ожидает `/languages-vue/`); README; пересборка всех пилотов + grep бандлов на `languages-vue`.
Данных и миграций не касается.

**Побочное наблюдение для ВСЕХ переехавших страниц:** старые адреса в корне (`/goals.html`,
`/workouts.html`, `/english.html` ...) после переезда отдают 404 — закладки владельца и
пользователей сломаются. `_redirects` здесь не работает (см. HANDOFF), поэтому предлагаю
крошечные заглушки-редиректы `<old>.html` (meta refresh + `location.replace`, сохраняющие
`search`/`hash`). Отдельная мелкая задача, лучше сделать один раз для всех страниц в конце фазы 2.

**Решение владельца (2026-09-29): вариант A одобрен. Сделано в v1.24 (агент 1).**

## 2. Логин и Онбординг

### Что нашла разведка
Жёстко прошитые адреса `/login.html` и `/onboarding.html` (не считая тестов и собранных бандлов):
- Классика: `config.js` (`requireAuth`, `logout`, `requireOnboarded` — 4 места), `login.js` (4), `onboarding.js` (3),
  `dashboard.js:3188`, `index.html` (редирект с корня).
- Пилоты: у каждой из 12 страниц по 2–3 места (`lib/supabase.ts` → `logout()`, `useX.ts` → проверка сессии и онбординга);
  плюс `web-login/src/lib/routes.ts` и `web-onboarding/src/lib/useOnboarding.ts`.
- `manifest.json`: `start_url` и `id` = `/login.html`. `sw.js`: `ASSETS` содержит оба адреса.
- Google OAuth: `redirectTo = origin + "/login.html"` (`login.js:130`) и `origin + ROUTES.login` (`useLogin.ts:77`).
- Уже сейчас: пилоты уводят незалогиненного пользователя на **классический** `/login.html`, а Vue-логин
  (`/login-vue/`) виден только по прямой ссылке. И после входа оба ведут на классический `/dashboard.html`.

### Предложение: два этапа, каждый безопасно откатывается
**Этап A — новый вход становится основным, ничего больше не трогаем.**
1. `login-vue/` → `/login/`, `onboarding-vue/` → `/onboarding/`; классика → `/legacy/login.html`, `/legacy/onboarding.html`
   (с `../` в путях и абсолютными переходами вместо относительных `dashboard.html`/`onboarding.html`).
2. В корне остаются **`login.html` и `onboarding.html` как заглушки-редиректы** на `/login/` и `/onboarding/`
   с сохранением `location.search` и `location.hash` (иначе сломается возврат из Google/`?code=`).
3. Все 32 прошитых редиректа продолжают работать через заглушку (один лишний переход). Это и есть защита от
   «блэст-радиуса»: ни один пилот не надо править в этот заход.
4. `manifest.json`: `start_url` → `/login/`, **`id` не менять** (это идентичность установленного PWA);
   `index.html` → `/login/`; `sw.js` (ASSETS + CACHE_NAME); `ROUTES.login/onboarding` в Vue-логине и Vue-онбординге.
5. `redirectTo` Google → `/login/`.

**Этап B — косметика, когда угодно:** заменить 32 адреса на финальные (`/login/`, `/onboarding/`), убрав лишний
переход. Заглушки остаются навсегда (закладки, установленные PWA, письма подтверждения Supabase со старыми ссылками).

### Зависимости и порядок
- **Делать ПОСЛЕ переезда Дашборда** на `/dashboard/`: Vue-логин и Vue-онбординг ведут на `/dashboard.html`
  (`ROUTES.dashboard`, `useOnboarding.ts`), и второй раз править их не хочется. Текущий порядок: Languages →
  Дашборд → Логин/Онбординг.
- Тесты: 22 теста `web-login`/`web-onboarding` + смоук-тесты AppShell (менять их не надо на этапе A).

### Действия владельца (не код)
1. **До деплоя этапа A** добавить `https://life-dashboard.orneryhero.workers.dev/login/` в Supabase → Authentication →
   URL Configuration → Redirect URLs. Если там перечислены конкретные пути, а не шаблон, без этого вход через Google
   после переезда сломается. Google Cloud Console трогать не надо: Google возвращает на callback Supabase, а не на сайт.
2. Проверить вручную на боевом домене (Google OAuth нельзя проверить локально): вход по email, регистрация → онбординг →
   дашборд, вход через Google, выход из пилота и из `/legacy/`, старая закладка `/login.html?x=1#y=2`,
   запуск установленного PWA.
