КАК ДОБАВЛЯТЬ ЗАПИСЬ: новая запись версии — В КОНЕЦ этого файла. Формат: `vX.YY — <пилот/страница, агент N, пункт BACKLOG>: <что сделано>`,
продолжение — строки с отступом в два пробела. Коротко: 3–6 строк (что изменилось, ключевые файлы, решения и допущения, что НЕ сделано,
число тестов). Подробности — в коммите и комментариях кода; текст для пользователя — в CHANGELOG (config.js). Когда записей больше ~15 —
старшие переносятся в docs/archive/ROADMAP_history.md (кто заметил перекос, тот и переносит).

ВЕЧНОЗЕЛЁНЫЕ ПРАВИЛА (сохранено из прежнего ROADMAP):
- Пилоты изолированы: каждая страница — отдельный mini-Vite-проект в web-<стр>/ со своими копиями общих кусков (date.ts, theme.ts, i18n.ts,
  supabase.ts, AppShell.vue); код между страницами НЕ импортируется, а копируется. Поэтому работа над разными страницами не конфликтует.
  Правка общего куска = правка во ВСЕХ копиях и пересборка каждого затронутого пилота.
- Единственная постоянная точка коллизии — SITE_VERSION и CHANGELOG_RU/CHANGELOG_EN в config.js (плюс version.json и собранная папка пилота).
  Как разрешать при пуше: 1) `git fetch origin && git log --oneline origin/main -5` — кто уже запушил и на какой версии; 2) если разошлись — сначала
  закоммитить своё, затем `git pull --rebase`; 3) в конфликте config.js остаются ОБЕ записи, порядок по номеру версии (больший сверху),
  SITE_VERSION = наибольший + 0.01; 4) `node --check config.js`, `python3 scripts/gen_version_json.py`; 5) для собранной папки пилота — взять любую
  сторону и ПЕРЕСОБРАТЬ из слитых исходников; 6) ещё раз `git fetch` перед push (за время резолва могли запушить снова). Пропуски в нумерации — не проблема.
- Деплой без общего wrangler-конфига (автодетект статики в корне): новую папку web-<стр>/ или /<стр>/ нигде отдельно прописывать не нужно.
