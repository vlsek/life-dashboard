# Визуальная регрессия перед релизом

Скрипт **scripts/visual_regression.py** проверяет локальные собранные папки в настоящем Chromium. Он не обращается к production и не заменяет проверку на физическом телефоне. Телефонный viewport — эмуляция Playwright.

## До изменения

После обновления main и сборки затрагиваемых пилотов сохранить исходный снимок:

~~~bash
python3 scripts/visual_regression.py \
  --themes dark,light,monet \
  --out /tmp/visual-before \
  --report /tmp/visual-before/report.json
~~~

## После изменения

После пересборки тех же пилотов выполнить сравнение с исходным снимком:

~~~bash
python3 scripts/visual_regression.py \
  --themes dark,light,monet \
  --out /tmp/visual-after \
  --baseline /tmp/visual-before \
  --report /tmp/visual-after/report.json
~~~

Проверять нужно все строки «ОШИБКА» и «замечание», а также скриншоты в каталоге /tmp/visual-after по viewport и теме. Доля изменившихся пикселей выше --threshold (по умолчанию 0.5%) — сигнал для просмотра, а не автоматическое доказательство дефекта. Отсутствующий baseline и невозможность сравнения должны оставаться явными замечаниями в отчёте.

Для узкой проверки можно указать страницы и viewport, например shop goals --viewports phone; темы задаются отдельно. light и monet поддерживаются тем же --themes, что и dark.

## Что считается проверенным

JSON-отчёт содержит scope local-built-folders, страницы, viewport, темы, путь к baseline, итоговые счётчики и результаты по страницам. По умолчанию он явно указывает:

- production_checked_manually: false
- real_device_checked_manually: false

После отдельной фактической ручной проверки можно добавить --mark-production-checked и/или --mark-real-device-checked. Эти флаги только фиксируют подтверждение оператора — скрипт не проверяет production и не подключает физическое устройство. Не ставить отметки по результатам локального Chromium.

## Минимальный порядок для релизного отчёта

1. Сохранить baseline на исходном main до правки.
2. Собрать затрагиваемые пилоты из актуальных исходников.
3. Снять новый прогон с теми же страницами, viewport и темами.
4. Просмотреть ошибки, замечания и изменившиеся скриншоты; приложить JSON-отчёт и указать путь к снимкам.
5. Отдельными пунктами написать, проверялись ли production и физическое устройство. Не приравнивать эмуляцию телефона к реальному телефону.

Тесты, vue-tsc, сборки и production deployment по-прежнему выполняет Клод; этот документ задаёт визуальную часть процесса и не заменяет остальные проверки.


## Защита путей CLI

Пути `--out`, `--baseline` и `--report` раскрывают `~` до начала проверки и затем используют одно и то же значение при валидации, чтении/записи и формировании JSON. Отчёт разрешён внутри каталога `--out` (например, `/tmp/visual-after/report.json`), но не внутри `--baseline`, не вместо каталога `--out` и не поверх одного из ожидаемых PNG-снимков.
