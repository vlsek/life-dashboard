# Оценка библиотеки графиков — BACKLOG 12:29

## Цель

Проверить замену самописного SVG-графика на интерактивный подход без преждевременного массового переписывания. Сначала сравнить на одном сложном случае — метрика типа «Подходы»: легенда по разновидностям, pie-маркеры по дням, подсказка, изменение периода, темы и доступность.

## Состояние на 2026-10-28

- Исходный график в web-dashboard/src/components/ChartBlock.vue и web-dashboard/src/lib/chart.ts самописный; чистая логика распределения особенностей уже вынесена в variationChart.ts и должна остаться независимой от рендерера.
- В web-dashboard/package.json сейчас нет графических библиотек в runtime dependencies.
- Добавлен исследовательский макет docs/mockups/chart-library-comparison.html: рядом представлены Apache ECharts и D3 + SVG на синтетических данных. Это демонстрация интерфейса/реализуемости, не production-код и не честный бенчмарк.
- Макет загружает библиотеки с CDN; открыть файл в современном браузере с доступом к CDN. Фактические размеры production-бандла, FPS/отзывчивость на телефоне, доступность с клавиатуры и поведение в темах не измерены в этой среде.

## Сравнение

| Критерий | Apache ECharts | D3-модули + собственный SVG |
|---|---|---|
| Tooltip, оси, zoom/dataZoom | Готовые компоненты, мало кода | Реализовать и поддерживать самим |
| Легенда с включением/выключением серий | Есть | Своя логика |
| Pie-маркер в точке | Нужен custom series / renderItem | Естественно собирается через d3-pie + d3-arc |
| Точный контроль фирменного UI | Хороший, но есть соглашения библиотеки | Максимальный |
| Начальная сложность | Ниже для стандартных графиков; кастомные маркеры усложняют | Выше: оси, подсказки, масштабирование, клавиатура — наша ответственность |
| Bundle | Потенциально крупнее; импортировать только нужные части и лениво | Можно импортировать только нужные модули; реальный размер зависит от сборки |
| Доступность | Не считать автоматически решённой; нужен текстовый эквивалент и проверка клавиатуры | Полный контроль, но все состояния и семантику надо делать вручную |

## Предварительная рекомендация

Не менять production-графики в рамках этого исследовательского среза. ECharts — первый кандидат, если после измерений он проходит бюджет загрузки и кастомный pie-маркер работает стабильно. D3 + SVG — предпочтительнее, если ECharts слишком тяжёлый или его custom series мешает дизайну/доступности. Не выбирать победителя только по внешнему виду макета.

## План проверки Клодом

1. Открыть docs/mockups/chart-library-comparison.html локально с доступом к CDN; проверить консоль и корректность pie-секторов в обеих реализациях.
2. Для честного production-сравнения создать две изолированные страницы/ветки с одинаковыми данными и функциональностью; не включать обе библиотеки в финальный бандл.
3. На production build снять размер добавочного JS до и после gzip/brotli; проверить, что код библиотеки действительно ленивый и не грузится до открытия графика.
4. Chromium, viewport 390×844 и desktop: прокрутка/изменение периода, tooltip, легенда, light/dark theme, reduced motion, клавиатура и текстовый эквивалент. Сравнить холодную загрузку и отзывчивость на большом диапазоне дат.
5. Зафиксировать измеренные значения и объём кода в этом документе, затем показать владельцу вывод и только после решения мигрировать production-компонент.
6. При миграции сохранить чистые функции подготовки данных и существующие контракты серий; не менять поведение графиков всех разделов одним коммитом.

## Ограничения макета

- Данные синтетические, а не из Supabase.
- Макет не доказывает корректность production build, tree-shaking или доступность.
- Точные размеры библиотек и мобильные показатели намеренно не придуманы: их нужно измерить в репозитории и браузере.
