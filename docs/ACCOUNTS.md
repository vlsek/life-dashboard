# Несколько учётных записей на одном устройстве (BACKLOG 1081)

Решения владельца (2026-10-15): вариант **А** — до 3 независимых входов (email/Google) на одном устройстве, каждая запись — отдельный
пользователь Supabase, **RLS и база не меняются**. Переключатель и в боковом меню, и в «Аккаунте». Вторая запись добавляется обычным
входом («Добавить запись»). Кнопка «Выйти» одна; при нескольких записях — окно «из какой выйти / из всех». Переключение — с перезагрузкой
страницы. Предупреждения про чужое устройство не нужно. Подпись активной записи — на усмотрение агента: **почта** (имя может совпадать).

## Как это устроено

Все пилоты и старые страницы берут сессию из стандартного хранилища `supabase-js` (`localStorage['sb-haxmgtflegsfpxieaydv-auth-token']`) —
клиенты в 18 пилотах **не меняются**. «Активная запись» — та, чья сессия лежит в этом ключе. Остальные записи лежат в `localStorage['accounts_v1']`
(массив `{id, email, session, savedAt}`, до 3; `session` — сырой JSON сессии). Код — `shared/accounts/accounts.ts` (без зависимостей).

- **Снимок.** Шапка (`web-header`, есть на каждой странице) при загрузке делает `captureCurrent()`: текущая сессия попадает в склад, токены обновляются.
- **Переключение.** `switchTo(id)`: снять текущую → положить выбранную в стандартный ключ → перезагрузить страницу.
- **Добавить.** `prepareAdd()`: снять текущую, освободить стандартный ключ **без выхода на сервере** → страница входа принимает новый вход → шапка на следующей странице снимает его в склад.
  При 3 записях заблокировано.
- **Выйти.** Одна запись — как раньше. Несколько — окно: «Выйти из этой записи» (серверный `signOut`, `removeAccount(id)`, активируется следующая) или «Выйти из всех»
  (`sessionsToRevoke()` — серверный отзыв остальных, `clearAll()`, на страницу входа).
- **Страница входа** показывает сохранённые записи кнопками «войти как…», чтобы не терять их после неудачного «Добавить».

## Порядок срезов

1. ✅ Модуль склада `shared/accounts/accounts.ts` + тесты (14), схема. Видимых изменений нет.
2. Шапка: снимок при загрузке; панель «Аккаунты» (список, метка активной, переключить, «Добавить запись»).
3. Выход: `logout()` пилотов → окно выбора при нескольких записях; серверный отзыв.
4. Страница входа: список сохранённых записей, режим «добавить».
5. «Аккаунт»: раздел «Записи на этом устройстве»; пункт в боковом меню пилотов.

## Риски

- Токен обновления ротируется при использовании: перед переключением всегда снимаем текущую сессию (тест «не теряет свежие токены»); у неактивных записей токен не трогается.
- Две вкладки: переключение в одной подхватывается другой при её перезагрузке; живое состояние второй вкладки до перезагрузки устарело (допустимо).
- Склад — те же данные, что и стандартное хранилище браузера: тот, у кого есть доступ к браузеру устройства, уже имеет доступ к сессии; новой поверхности атаки нет (владелец: предупреждение не нужно).
